# AbleMind 的一句话是什么?

> **站着不动的问题**(Jobs 第一测试):
> 补完——**「AbleMind 是让〔谁〕能〔做什么〕,于是 TA〔变成谁〕。」**
> 并由这一句话**裁定三件事**:① 首屏主角是什么 · ② 砍掉哪些并行界面 · ③ 那个 60 秒「魔法时刻」demo 长什么样。

*为什么这道产品题落在哲学库的 QA:这个库是 3.0「立场随时间演化、旧答不删」方法论的原型/狗粮。我对自己产品定位的 conviction,本身就是一条该被追踪的时间序列——用这道题给自己的方法吃一口狗粮。本题 recall 源 = `dpagt/docs/adr/021–024` + 会话,不是哲学 wiki 域(故 `recall-scope: []`)。可按需镜像到 valu_air。*

**为什么是动态题**:这句话一旦拍死,半年来「引擎 vs 图谱 vs casting」的资源分配之争**自动有了裁判**——服务这句话的留,不服务的砍。在拍死之前,它会随我想清楚而变;每次重答**追加不覆盖**,变化轨迹本身是产出。

**Claude 的押注:A。** 理由一句话:B 是可被替代的(通用 chat 在逼近),A 是不可替代的(conviction-over-time 这份资产别人没有);3.0 vision 你自己的原话「人的知识体系和 Agent 的上下文是同一个对象」只有 A 兑现。

**但真正的张力,是 A vs B——而且 B 在偷偷赢。**
代码不会撒谎:最近 60 个 commit,`backend_dp` 111 次 vs `frontend_dp` 63 次,劲全在 casting / 模型路由 / latency——**你的劳动实际在做 B,你的叙事(4 份 ADR)在想 A。** 嘴上 A、手上 B,是这半年最大的内耗。拍板 = 让嘴和手对齐。

**怎么算答对了(验收标准,不是嘴炮):** 那个 A 的 60 秒 demo **现在跑不出来**——因为 `wiki_workspace.py:115` 的 `/recall` 端点造好了却没接进 `ablework_context.py:297`(live turn 只注入手点的 `focus_node`),且前端无自动存入(`burrow-dashboard.tsx:262` 空态指向产品外)。**判答对的唯一标准:选定的那句话,它的 demo 能不能在产品里真跑。** 跑不出来的定位,是 PPT。

**缺口 / 待验证(下次重答前该有进展):**
- [ ] A 的 demo 的最小闭环:`/recall` 接进 live turn 的一行 + 一个「存入对话」动作。能跑 → A 可信;跑了没人用 → 退 B。

### 2026-06-20 · 第2答(Claude 综合版)

**这一答的来历:** 四个互不可见的来源——我首答的单独分析 / 你自己的「嘴 A 手 B」/ scrub 过的 4 模型 panel(codex·grok·agy·kimi)/ philo_air 已跑通的原型——收敛到同一句:

> **A 是目的地,B 是今天的诚实现实,自动捕获泵是唯一把 B 变成 A 的东西。**

panel 票面 3B(codex/grok/agy)+ 1A(kimi),但**没有一票在「A 还是 B」上真分歧**:三张 B 票都明说「A 才是护城河,只是今天跑不出来」,那张 A 票也设了「6 个月泵跑不通就降格 B」。分歧只在『今天该把自己叫 A 还是 B』,实质全员一致。所以——

**完整答案不是选一个候选,是一个有序承诺:** 名分押 A · 诚实认今天是 B · 下一增量只做捕获泵 · 用真用户卡死 deadline。

**当前立场:** 押 A 作目的地,同时诚实承认今天产品事实上是 B。拍板权在你——这是这场对话里唯一我替不了的决定。

**一句话定位:**
AbleMind 是让二级投研分析师能把每个标的的 conviction **不靠手维护、自动保持最新且可查证**的,于是 TA 从「每次投委会前花两天重推我们到底信什么、人一走知识就带走」变成「**任何早上一登录,账本已 current,且会提示哪条判断跟今天的新数据打架了**」。

**裁定:**
- **首屏** = 账本的「漂移 / 下一件事」面(哪条 conviction 跟新数据打架 → 去定调)+ chat 作输入口。
- **砍** = ① 研究 chat 当英雄的那套并行 UI(那是 B 的首屏)② 3D 星云降为习惯层/可唤起(本会话已证它喂不饱时接近噱头)③ 模型选择面板后台化。
- **demo** = 昨天聊过宁德 → 今早财报出 → 一登录账本已把宁德论点标红「跟新财报打架,去定调」→ 点开,上次论证 + 今日数据并排。**此机制已在 philo_air 心跳员真实跑通 = 移植,不是发明。**

**理由:** B 可被替代(通用模型正追平「更快更懂金融的 chat」),A 不可替代(conviction-over-time 是别人没有的资产,且唯一兑现你那句「人的知识体系 = Agent 上下文是同一个对象」);A 的机制已被 philo_air 验证——但 A 的命门是自动捕获泵,**泵死则 A 退化成 PPT**。

**demo 能跑了吗:不能。** 卡在两处,第二处更要命:
- **注入环**:`/recall`(`wiki_workspace.py:115`)没接进 live turn(`ablework_context.py:297` 只注入手点的 `focus_node`)+ 前端无「自动存入」。
- **捕获环(真致命)**:自动捕获泵已退役、无替代 → **账本无源**,永远 current 不起来。手动 seed 能演 demo,但**不能证明 A 成立**。

**和上次比(首答 → 第2答):立场未翻**(仍押 A 为目的地),被独立 panel 触发**两点收紧 + 一处自我更正**:
1. **「A vs B」被证伪为伪命题**——4 个互不可见的模型一致收敛到「A=目的地 / B=今天 / 泵=生死手」;`backend 111 : frontend 63` 被三个没看过这句话的模型独立读成「手在造引擎、嘴在说 A」。
2. **验收标准拧紧**:从「demo 能跑」→「真用户会喂 + 捕获泵跑通」。demo 靠手动 seed **不算数**(别卖一个跑不出来的 A)。
3. **自我更正**:首答我把命门定在「`/recall` 没接进 `ablework_context`」(注入环);第2答我承认**更致命的是捕获环**——`/recall` 就算接通,也只是让 agent 读到一个**空账本**。读的管子接错了重点,**源头的泵才是生死手**。

**待你拍的那一个 yes/no(+ deadline):**
> 「下一个增量**只做自动捕获泵 + 卡一个真实分析师验证**,不再调引擎、不再接一行 `/recall` 充数」——做不做?
- **做** → 押 A 成立;6 个月(wall-clock,真用户喂数据看留存)内泵跑不通 + 没人喂 → 诚实降格「B + A 叙事」。
- **不做** → 你就是个 B,那就别在 ADR 里写 A,把叙事也对齐成 B。

(kimi 首轮那段「脱靶」反而是免费外部警告,独立印证了「第三个半脑」风险:别让工程完备盖过 PMF 未验。)
