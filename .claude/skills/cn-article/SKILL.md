# 写好中文文章 (cn-article)

## 一句话心法

**体裁不决定写法,读者状态决定写法。** 公文、研报、科技博客、公众号不是四套方法,是同一根"金字塔↔叙事"轴上的四个刻度——由读者的**权力关系**(服从↔自愿)和**注意力状态**(赶时间↔愿沉浸)决定配比。

```
纯逻辑 ←────────────────────────→ 纯叙事
公文报告   研究报告   科技博客   微信公众号
```

## 先分是哪个模式

- **写 / 润色**(帮我写、这篇怎么写、搭骨架)→ 走「写作五步」。
- **吃案例**(吸收这篇、拆进案例库、学一下这个爆款)→ 读 `references/案例吸收协议.md` 执行。

## 模式 A · 写作五步

1. **判读者** — 定位读者两个坐标:权力关系(服从↔自愿)、注意力(赶时间↔愿沉浸)。这一步决定一切。**不确定就问一句**(写给谁看、在哪发),别猜。
2. **定配比** — 据读者定"金字塔:叙事"的比例、悬念浓度、"我"的浓度、结论位置。选体裁 → 读 `references/四体裁配方.md` 对应小节。
3. **搭骨架** — 先列 outline 再写。用勾立转收,或体裁专属骨架(公文三段式 / 研报 SCQA / 博客问题-方案)。理论见 `references/双轴与勾立转收.md`。
4. **写** — 凤头(勾)要狠、猪肚(立)要实、豹尾(收)要留东西;转要"回头看必然"。中文的气与去翻译腔见 `references/中文语境.md`。
5. **自检** — 过勾立转收自检 + **念出来**查翻译腔 + 比对 `cases/_index.md` 同体裁复现模式。

## 模式 B · 吃案例(技能长大的唯一方式)

用户投喂真实范文时,**不要只夸好,要拆解入库**:按 `references/案例吸收协议.md` 生成拆解卡 → 存 `cases/` → 更新 `cases/_index.md` 的复现模式。跨案例的共性(≥3 卡共现)才升为"模式"。只存不炼等于没长大。

## 本库联动(可选)

在 philo_air 库内时,本技能与 `wiki/expression/` 表达域同源:
- 写前可 recall `wiki/expression/`(框架页 + 案例库),取更细的框架定义。
- 吃案例时,除存 `cases/`,可选 ingest 进 `wiki/expression/案例/`(作 `案例` 节点,`exemplifies` 连到所用框架),走 auto-wiki 协议。
- 库外使用则纯自足,忽略本节。
