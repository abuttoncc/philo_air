# 案例吸收协议（技能长大的引擎）

用户投喂真实范文（爆款公众号 / 好研报 / 高赞技术博客 / 被批的公文……）时执行。目标：把一次性的"这篇真好"沉淀成**可复用的结构知识**。

## 流程

1. **收料** — 拿到原文（链接 / 全文 / 截图）。问清两件事：**哪个体裁？为什么被判定为好**（打开率 / 转发 / 点赞 / 被引 / 上级批了）？好的证据决定它值不值得入库、以及入库后可信度多高。
2. **拆解** — 按下方模板逐句标注，填一张拆解卡。重点是**逐句指出勾/立/转/收落在哪、用了什么招**，不是泛泛而谈。
3. **入库** — 存 `cases/{体裁}/{slug}.md`（slug＝一句话能认出的名字）。在 `cases/_index.md` 案例登记表加一行。
4. **提炼** — 扫 `cases/_index.md` 同体裁已有卡：**某手法在 ≥3 张卡出现 → 升为该体裁的"复现模式"**，写进 `cases/_index.md` 复现模式区，并注明"何时用、何时不灵"。**这一步是关键，别只存不炼。**
5. **（可选）进 wiki** — 在 philo_air 库内，可 ingest 进 `wiki/expression/案例/`（作 `案例` 节点，`exemplifies` 连到所用框架），走 auto-wiki 协议、留 run 档。

## 逐拍拆解
- **勾（凤头）**：开头怎么勾的？用了什么（痛点/悬念/金句/画面/数据反差）？抄下原文首句。
- **立（猪肚）**：怎么撑起来、给了读者什么可预测的模式？节奏如何？
- **转**：转在哪一句？打破了什么预期？回头看必然吗（铺垫够不够）？
- **收（豹尾）**：结尾留了什么（社交货币/建议/动作/金句）？抄下原文末句。

## 提炼规则

- 一张卡 = 一篇具体范文；一条模式 = 跨 **≥3 卡**的共性手法。别把单卡当模式。
- 模式要**可迁移、可证伪**——能说清"什么时候用、什么时候不灵"，不是"开头要吸引人"这种废话。
- **反例同样入库**（标 anti-pattern）："为什么扑街"和"为什么爆"一样值钱。
- 提炼出的模式若与 `cases/_index.md` 现有先验冲突 → 用真实案例**校准或推翻**先验，并在该模式后注一句依据。
