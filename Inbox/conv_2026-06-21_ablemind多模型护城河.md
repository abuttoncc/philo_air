## 候选 1 — Cursor 真教训:死因不是"单模型依赖",是"薄分发层 + 零留存 + 供应商即对手"
- **claim**:Cursor 复盘最反直觉的一条——**它本来就是多模型的(用户可自选 Claude/GPT/Gemini),却被挤死;
  Claude Code 是纯单模型的,却在赢。赢家比输家更"模型锁定"。** 这把"单一模型依赖=死因"直接证伪。
  真死因 = **不拥有模型的薄分发层 + 零转换成本(产出=代码,落用户 repo,人走带走) + 无累积专有资产**,
  且站在一个**既是供应商又是竞争对手**的模型之上(付零售价/对方拿批发价,毛利≈0)。用 [[竞争优势模式]]
  复制成本反演判:Cursor 整个就是"白酒"。**含义**:"我要做多模型"若是冲着"治 Cursor 的病",药没对症。
- **why-long-term**:纠正一个**会反复误导资源分配**的错误归因(把死因归给模型数量);跨会话要用的判据。
- **时间档**:T2 原则(+ 溯源里几条 Cursor 数据是 T0/T4,作论据不单独建节点)。
- **连接提示**:`develops` [[竞争优势模式]](复制成本反演);`references` [[conv_2026-06-21_ablemind护城河]] 候选1(白酒易仿)。

## 候选 2 — 多模型路由/eval/异构拼接 = "船票(生存基底)",不是"船(护城河)"
- **claim**:模型无关 + eval 上岗适配 + 异构拼接(DeepSeek 缺多模态自己拼、对话模式)**本身是白酒易仿**
  (OpenRouter/LiteLLM/Vercel AI SDK 现成)——是**先发优势,不是护城河**。但它有真价值:**拆脆弱性**
  (永不被任一家定价绞杀)= **结构性生存优势**。而**活着是护城河复利的前提,公司先死账本再厚也没用**。
  故定性:**多模型是让你活到账本变厚的「船票」,不是「船」。** 拆脆弱性(防守) ≠ 建护城河(进攻),
  用户主张里这两件事被叠在了一起。
- **why-long-term**:给"多模型"一个**精确的战略地位**(必要基底/table stakes,非差异化卖点),防止把船票当船卖。
- **时间档**:T2 原则。
- **连接提示**:`develops` [[竞争优势模式]];`critiques` 「多模型即护城河」主张;`references` [[不可替代性拷问]]。

## 候选 3 — 主要矛盾(矛盾分析结论):不是"模型够不够多",是"异构产出沉淀在哪"
- **claim**:用 `contradiction-analysis` 拆开,**主要矛盾 = 产出沉淀在用户处(零留存,答完即走)
  vs 沉淀进可累积的 conviction 账本(转换成本,越用越黏)**。判据:解这条,其余矛盾全塌缩——
  路由降格为账本的配送机制(M2)、eval 的标准答案变成账本本身(M6)、防守/进攻各归其位(M5)、
  无感/有感知道该藏路由露资产(M4)。反向验证:把路由/eval/拼接全做到顶却不碰这条 →
  得到一台优秀的**商品路由器,零留存 = Cursor**,护城河纹丝未动。**主要方面**:今天占支配地位的是
  "沉淀在用户处"(捕获泵退役、账本无源)→ **故 AbleMind 今天的性质 = Cursor 那侧的商品路由器,
  护城河真值=0,不因模型少,因产出外流。**
- **why-long-term**:这是把"护城河"问题**收敛到单一可执行抓手**的根结论(抓住牛鼻子);指导一切资源分配。
- **时间档**:T2 原则。
- **连接提示**:`develops` [[conv_2026-06-21_ablemind护城河]] 候选2/候选3;`grounds` 捕获泵设计;
  与 [[conv_2026-06-20_ablemind飞轮]] 候选2「进料口=被漏建的那半」互证。

## 候选 4 — eval 的护城河条件:标准答案从"公开基准(商品)"切到"已兑现判断(专有)"
- **claim**:"取众家之长"真正的承重点是 **eval 的标准答案从哪来**。公开基准当裁判 → 你的路由和别人
  收敛到同一套 = 白酒;**"该用户/机构历史上已兑现的判断"当裁判 → 这套 eval 谁都拿不到 = 不可复制**。
  但专有 eval **只在账本真在累积时才存在** → 又绕回那枚生死手(捕获泵)。所以连"eval 选模型"这件最像
  护城河的事,其护城河性也**寄生在账本累积上**,而非寄生在 eval 工程本身。
- **why-long-term**:堵死"那 eval 总该是护城河了吧"的退路;把 eval 的价值锚死在专有累积语料上。
- **时间档**:T2 原则。
- **连接提示**:`part_of` 候选3(同一主要矛盾的 eval 切面);`references` [[AbleMind 的一句话定位]] 生死手论。

## 候选 5 — 性质判定:非对抗性为体(双写可调和)、对抗性为枢(自动点火 vs 手动)
- **claim**:主要矛盾性质 = **非对抗性为体**——产出能**同时**落用户工作流(无感)+ 双写一条结构化痕迹
  进账本(沉淀),两侧不必二选一,用"重设计"解(飞轮"存入"半)。**但内含一个对抗性枢纽:自动点火 vs
  手动触发。** 默认引力把产出冲向用户侧(自然态=Cursor),要它沉淀必须有主动架构力持续施加。
  **最致命的方法错配 = 把捕获泵当非对抗性的"锦上添花、建好挂手动即可",而它实为对抗性的
  "必须自动点火,否则整条护城河是假的"**——处理不当,非对抗性的主要矛盾会**退化成对抗性**
  (产出全外流、账本永空、坐实又一个 Cursor)。这正是 QA 钉死的"生死手",和飞轮篇候选4
  "泵建好却只挂手动从不点火"的失败模式同构。
- **why-long-term**:给主要矛盾配上正确的解法类型(果断取舍枢纽 + 重设计本体),防方法错配。
- **时间档**:T2 原则(陋居自动化"捕获免费、晋升收紧"的同源教训)。
- **连接提示**:`grounds` 捕获泵自动点火设计;`develops` [[conv_2026-06-20_ablemind飞轮]] 候选4;
  `references` [[AbleMind 的一句话定位]] 待拍的 yes/no(下一增量只做捕获泵+真用户)。
