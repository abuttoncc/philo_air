# Philo Vault · 表达领域本体契约

> `wiki/expression/` 的本体定义。`ingest`/`recall` 前先读本页。引擎规范见 `.claude/skills/auto-wiki/`，
> 与 [[wiki/metaphysics/_ontology|metaphysics 母本]] **共用同一套 6 档时间模型、退役不删除协议与三分铁律**——
> **本页只声明 表达 领域特有的节点类型与受控关系词表**，其余一律以引擎 + metaphysics 母本 契约为准。

## 0. 总原则（同 metaphysics 母本）
1. **节点 / 数据 / 边 三分**：数值绝不是节点（进 data.db）；关系是边不是页；分类标签是边不是页。
2. **编译单向**：`Inbox(散文) → ingest → wiki(本体)`。严谨只用在已结晶的知识。
3. **退役不删除**：T1/T2/T3 任何变化都是「旧行封 valid_to + 插新行」，永不 DELETE，必有 T4 事件盖章。

## 0.5 中心实体：表达 = 四 facet 归一
**表达**是本域中心实体，覆盖四种模式（facet），彼此共享同一套结构骨架、只是媒介与目的不同：
- **叙事表达**（讲**动人**）：勾立转收、救猫咪、起承转合、相声——时间轴，管注意力与情绪。
- **思想表达**（讲**清楚**）：金字塔原理、SCQA、MECE、结论先行——空间轴，管逻辑与说服。
- **产品表达**（产品即传达）：发布会/demo/产品叙事——前两者在产品媒介上的落地（乔布斯发布会＝叙事×产品）。
- **可视化的视觉表达**（讲**得一眼看懂**）：把「思想表达」已经定好的逻辑关系（对比/因果/权衡/包含/循环……）翻译成具体图形（2×2矩阵/瀑布图/漏斗图/韦恩图……）——下游消费上游：本 facet 不产生新逻辑，只解决"这个逻辑结构该长成什么形状"。金字塔原理在本 facet 下有第二重身份（同一节点，双 `classified_as`）：思想表达管到"论点分组+页序"，可视化的视觉表达接手"页内视觉怎么摆"。参考框架：Zelazny《用图表说话》五种数据关系、Duarte 六大图形族(Flow/Structure/Cluster/Radiate/Pictorial/Data)、Abela Chart Chooser、Assertion-Evidence、久恒启一図解思考。**待 ingest**（2026-07-07 已完成 P0 阶段的文献调研，尚未写入节点，见 log.md）。

> facet **不是目录、不是页**，是一根 `classified_as` 分类轴（见 §4），每个框架/概念按服务哪种表达打标、按它分桶着色。

## 1. 节点判据（同 metaphysics 母本 的「能不能指向就是这一个」）
能用手指指向「就是这一个」、明年同名还指同一个 → **实体**；必须先讲一段机理才懂 → **概念**。
**本域关键提示**：有专名、可整体指认的**结构框架**（金字塔原理 / 救猫咪十五拍 / 起承转合 / 相声四段式）
归 `框架/`（既不是"概念"也不是"分析"）；框架的**组成部件**（勾/立/转/收、SCQA 四要素、垫话/瓢把儿/正活/底）
是概念，用 `part_of` 挂回所属框架。

## 2. 节点类型（=目录=图谱着色）
| 类型 | 子目录 | 判据 | 例子 |
|---|---|---|---|
| 实体·人物 | `人物/` | 有专名的表达理论源头，能指向就是这一个 | 芭芭拉·明托、布莱克·斯奈德、杨载、亚里士多德、罗伯特·麦基 |
| 实体·著作 | `著作/` | 有专名文本，书名号《》开头命名 | 《金字塔原理》《Save the Cat!》《诗法家数》《故事》《修辞学》 |
| 框架 | `框架/` | **有专名、可整体指认的结构模型/模板（本域签名类型）** | 金字塔原理、救猫咪十五拍、起承转合、相声四段式、勾立转收、SCQA、三幕结构 |
| 概念 | `概念/` | 必须先讲机理才懂的抽象/局部技法 | 结论先行、以上统下、归类分组(MECE)、逻辑递进、悬念、预期管理、包袱、三翻四抖、移情、首尾呼应 |
| 案例 | `案例/` | 被拆解的具体表达样本（可指认主体+时段，功能是例证某框架/技法） | 乔布斯斯坦福演讲叙事拆解、某 pitch 结构复盘 |
| 分析 | `分析/` | 研究课题派生视图（删了不影响本体） | 叙事结构跨传统综述、表达双轴模型综述 |
| 来源 | `来源/` | 讲义/文字稿/摘录（注明 source_type） | 叙事结构研究笔记、金字塔原理摘录 |

> 易踩的坑：「三翻四抖」像框架但它是**局部技法** → `概念/`，用 part_of 挂到「相声四段式」；
> 「勾立转收」是本库综合出的**元框架** → `框架/`；「结论先行」是金字塔的部件概念 → `概念/` + part_of。
> 「乔布斯」「苹果」已在 [[产品哲学]] 建过 → **全库只建一次**，本域案例只连边引用，不重建（命名纪律）。

## 3. 受控关系词表（表达 特有；通用词沿用 metaphysics 母本）

本域特有增量：
- `对应`（框架元素/概念 ↔ 另一框架的元素/概念，跨框架等价对应）：**本域签名边**（位置相当于母本的 grounds）。
  例：勾 →对应→ 起；起 →对应→ 垫话；转 →对应→ 抖包袱；金字塔 SCQA 的冲突 →对应→ 叙事的转。
  整份跨传统综述就编码在这类边里。双向语义，lint 允许任一方向登记一次即可。
- `exemplifies`（案例 → 框架/概念，借自 [[产品哲学]]）：被拆解的表达样本例证某框架/技法。
  例：乔布斯斯坦福演讲 →exemplifies→ 勾立转收。

沿用母本：`proposed_by`(框架/概念→人物) · `authored_by`(著作→人物) · `appears_in`(框架/概念→著作) ·
`part_of`(概念→框架，用于"框架的组成部件") · `instance_of`(具体框架→抽象框架，如 救猫咪十五拍→三幕结构) ·
`supports`/`critiques` · `develops`(后继→前驱) · `classified_as`(→分类标签) · `references`(分析/来源→任意)。

> lint 时以本表对照；双写：页面 `frontmatter.relations[]` + `data.db relations 表`。

## 4. classified_as 分类轴（标签是边不是页，可按它分桶着色）
- **表达模式（本域主轴）**：`叙事表达` / `思想表达` / `产品表达` / `可视化的视觉表达`——每个框架/概念至少打一个，可跨打（如金字塔原理＝思想表达＋可视化的视觉表达）。
- 逻辑型 / 叙事型（金字塔=逻辑型；勾立转收=叙事型）。
- 演绎 / 归纳（金字塔横向关系）。
- 整体框架 / 局部技法。

## 5. 跨域连接
- `references` 连 [[产品哲学]]：**产品表达** facet 的案例（乔布斯发布会等）引用产品哲学的概念/人物；
  **同一专名物（乔布斯、苹果）全库只建一次，本域连边引用，不重建**。
- 可选跨方向签名边：[[认识论]] →`grounds`→ 表达（说服＝改变信念，认识论奠基说服观），honor 库"理论奠基实践"设计。
