# 拾遗员 · capture(飞轮的进料口 stage ⓪)

把 Claude Code 对话里**会蒸发的 conviction** 拾成 Inbox 候选,让知识库从日常对话自己长,而不是等人手喂。是飞轮缺的那半——**进料口**。

**与 dpagt 的 `dream.py` 同构**:在原型库先把「自动捕获」跑通、验准候选质量,再移植回产品的 Dream 调度器。**原型证明,产品照搬。**

**收口纪律(陋居四原则)**:
- **捕获免费**——宁滥勿缺落候选(Inbox 未 `compiled`)。
- **晋升收紧**——进 wiki 走 digest-inbox 的 auto-wiki 纪律 + 08-Ops review。
- **产出收口**——LLM 抽的候选不直写正典,人/digest 复核才晋升。
- **确定性优先**——读转写/压实/记账走 `capture.py`(纯 stdlib),只有「抽候选」用 LLM。

## 飞轮位置

```
⓪ 拾遗员(本)        ① 分诊员/digest-inbox      ② auto-wiki ingest
对话 → Inbox 候选  →  分诊 crystallize/reference  →  wiki 正典 + data.db
   (捕获免费)              (晋升收紧,过闸)            (退役不删除)
```

拾遗员排在 CLAUDE.md §三 生命周期「①发散提问」之前——它是把「对话」变成「Inbox 进料」的那台泵。
